# Event table

`mru_events.csv` is the label set. Every row must be a real, sourced
observation; see `HARVEST_LOG.md` for how the current rows were compiled
and how confident each one is. Synthetic rows for dry runs live in
`synthetic_events.csv` (generated by `scripts/make_synthetic.py`) and must
never be merged into this file.

## Columns

| column | values | notes |
|---|---|---|
| event_id | free text, unique | e.g. `2024-02-11-blue_bay-1` |
| date | ISO date `YYYY-MM-DD` | first day the presence was reported |
| date_precision | `day`, `week`, `month`, `unknown` | only `day` rows are used for scoring |
| beach_id | id from `config/beaches.yaml` | add a beach there if needed |
| lat, lon | decimal degrees, optional | for reports away from a listed beach |
| species_group | `physalia`, `cubozoa`, `scyphozoa`, `unknown` | drives which model is validated |
| species | scientific name if known | leave blank otherwise |
| count_class | `single`, `few`, `many`, `mass`, `unknown` | NCG alerts rarely give numbers |
| stings | integer, optional | reported sting count |
| source_type | `coastguard`, `beach_authority`, `hospital`, `press`, `tripadvisor`, `social`, `lifeguard`, `other` | |
| source_url | URL or archive reference | required for `press`, `tripadvisor`, `social` |
| confidence | `high`, `medium`, `low` | high = year explicit or two sources agree; medium = year inferred from weekday plus context; low = ambiguous year or URL not captured |
| notes | free text | |

## Absence records

Absence matters as much as presence. When lifeguards or partners can log
"checked, none seen" days, add them to a separate `mru_absences.csv` with
`date, beach_id, source_type, notes`. The validator will use them as true
negatives once they exist.
